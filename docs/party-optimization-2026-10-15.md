# 派對廣播與房間儲存優化對照

2026-10-15。舊版基準為 `58d354e3d6b93cf88502f6d70221ed0613c68479`，新版為目前工作目錄。

## 變更

- 新版派對連線只傳變動欄位、變動玩家欄位與必要的排名順序。首次連線、重新連線及結束時傳完整狀態。舊版客戶端仍使用原有完整狀態格式。
- 每次廣播共用排序後的玩家列表；同一玩家多分頁共用經權限過濾的快照，同一玩家列表的差異也共用計算結果。主持人音源與個別答錯回饋仍保持隔離。
- 房間固定題庫只寫入 `party_catalogs` 一次，動態狀態只保存牌組 ID、玩家分數、回合與必要歷史。不再每次答題都解析及寫入整份題庫。
- 重用 SQL prepared statements，派對 autocomplete 作答以歌曲 ID 直接查詢目前開放的歌曲，避免讀取整份公開題庫。
- 每次有效作答仍先同步提交 SQLite 交易再廣播，沒有延後寫入分數、合併搶答次序或減少計分事件。

## 相同環境的前後比較

以 `scripts/compare-party-load.mjs` **依序**啟動兩個版本，使用同一台 Windows 電腦、本機回環網路、各自隔離的 SQLite WAL 資料庫、完全相同的 558 首合成題庫。每版 2 個滿員派對，100 位玩家加 2 位主持人，共 102 條 SSE。舊版完整狀態、新版 compact 協定。

每版先觀察 20 秒連線，再跑每秒 20 次操作、持續 30 秒，接著三輪密集廣播。操作混合與上一輪壓測相同：60% 錯誤答案提交、20% 曲庫讀取、20% 排行榜讀取。廣播每房 10 位玩家放棄、每房 5 個並行請求、兩房並行，再揭曉／下一首／開始。這與前次正式站壓測的工作負載一致；它不等於 100 人同時全部答對。

| 指標 | 舊版 | 新版 | 比較 |
| --- | ---: | ---: | --- |
| 混合操作請求 p95 | 137 ms | 41 ms | 降低約 70% |
| 混合操作請求 p50 | 64 ms | 24 ms | 降低約 63% |
| 混合操作健康檢查 p95 | 25 ms | 1 ms | 健康請求等待降低 |
| 三輪全員廣播 p95 | 761 / 746 / 781 ms | 400 / 277 / 357 ms | 三輪 p95 的中位數降低約 53% |
| 每輪 SSE 接收量 | 10.00 / 9.98 / 9.98 MB | 0.99 / 0.99 / 0.99 MB | 減少約 90% |
| 每輪廣播總耗時 | 1.89 / 1.95 / 1.87 秒 | 0.99 / 0.79 / 0.84 秒 | 三輪皆縮短 |
| 每房平均動態狀態 JSON | 335,256 bytes | 24,488 bytes | 減少約 93% |
| 混合請求失敗 | 0 / 600 | 0 / 600 | 無失敗 |
| 廣播操作失敗 | 0 / 78 | 0 / 78 | 無失敗 |
| 意外 SSE 斷線 | 0 | 0 | 無斷線 |

JSON 大小取三輪結束並完成房間後的資料庫狀態，不是整個資料庫大小，也不是直接量測每次磁碟寫入量；固定題庫仍另存一次，沒有刪除歌曲資料。廣播 p95 為從送出操作到房間所有客戶端觀察到該版本或更新版本，包含 HTTP 與 SSE。

**這是本機受控 A/B 結果，不能宣稱 Zeabur 已從約 2 秒降到 357 ms。** 上一次正式站的網路、Linux 磁碟與機器資源不同。新版尚未推送或部署；正式站仍是舊版，需要上線後用 `--compact=1` 另做驗收，且舊 PWA 使用者更新 App 後才會使用精簡協定。

## 正確性與驗證

- `npm run check`、`npm test`、`npm run build` 全部通過，68 個後端測試＋146 個前端測試，共 214 個。
- 50 位獨立 HTTP 玩家同時答對：一半使用完整狀態、一半使用 compact，所有玩家最終排名與 HTTP 狀態完全一致，名次與分數沒有重複；compact 接收量低於完整狀態的 35%。包含手動輸入與 autocomplete song ID。
- 草稿歌曲 ID 不能作為正確答案；主持人音源不洩漏給參賽者，答錯回饋只通知該玩家。
- 舊房間原子轉換、寫入錯誤回滾、重新啟動後分數與牌組、同版本在線狀態更新、PWA 背景恢復、錯誤 patch 基準、原有房間逾時與結算流程皆有驗證。
- Docker 前後端皆已加入共用協定模組的 COPY；本次完成 Node／Vite 建置，沒有宣稱執行遠端 Docker 部署。
- 四個本機測試房間皆完成，兩個隔離測試伺服器已停止；本次沒有在正式站建立測試房間或修改資料。

儲存格式更新後，舊房間第一次有效寫入才轉成 `storageVersion: 2`。正式部署前需備份 SQLite；若回退到舊後端，需同步還原升級前備份，不能只退映像。升級與相容格式說明見 README。

原始資料：`data/party-optimization-comparison/comparison.json` 及其 `before/load`、`after/load` 子目錄。這些資料留在忽略版控的 `data/`；測試 cookie 不可提交。比較命令：

```powershell
node scripts/compare-party-load.mjs --before=data/party-before --out=data/party-comparison-new-run
```

`data/party-before` 是舊版 Git archive 的隔離副本。使用新輸出目錄重跑，勿指向正式資料卷。
